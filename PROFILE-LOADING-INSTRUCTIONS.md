# Инструкция: прогрузка профилей SIM в AUC (через EKI и транспортный ключ)

> **Кому:** сотрудникам отдела ИБ, работающим с тестовым стендом pLTE-in-BOX (192.168.0.9).
> **Что делает инструкция:** за 5–10 минут прописывает профиль нового абонента (SIM)
> в ядро сети **в зашифрованном виде** и проверяет результат.
> **Подробности архитектуры:** `EKI-TK-ENCRYPTION.md`; формат файла — `.deploy/profiles/README.md`.

---

## 1. Что нужно знать (2 минуты)

- В файл загрузки ключ абонента (Ki) **не попадает в открытом виде**. В файле —
  `E_KI` (ключ, зашифрованный транспортным ключом TK, AES-128-ECB) и `EKI` —
  **номер** транспортного ключа.
- Сам TK хранится в KMS (OpenBao) на стенде. В файлах, git и логах он не встречается.
- Если что-то не так (неверный EKI, файл повреждён в transit, KMS не доступен) —
  прогрузка **отказывается целиком**, в базу ничего не пишется (принцип fail-closed).
- Повторный запуск того же файла безопасен: дубликаты не создаются.
- Файл с eKi можно свободно пересылать (scp/почта) — это и есть «защищённый» вариант
  передачи профилей вместо plaintext-файлов с ключами.

## 2. Подключение и быстрая проверка стенда

```bash
ssh mazay@192.168.0.9
cd ~/open5gs-compose
bash .deploy/scripts/verify-encrypted-stack.sh
```

Скрипт только читает состояние (безопасен, можно запускать в любой момент).
В конце должно быть `=== Verification done ===`, в секции 3 — `subscribers: N`,
в секции 9 — `EKI 1: current_version …` (существующие транспортные ключи).

## 3. Шаг 1 — убедиться, что транспортный ключ существует

```bash
bash .deploy/scripts/tk-mgmt.sh meta 1
```

- Вывод `current_version: 1` → ключ с номером **EKI=1** активен, идём к шагу 2.
- Вывод `not present in the KMS` → ключ не создан, создайте его:

```bash
bash .deploy/scripts/tk-mgmt.sh create 1
```

Ключ генерируется и сразу хранится в KMS; его значение никуда не выводится.

**Если ключ получен от поставщика профилей (КПХД)** — это нормальный боевой поток:
ключ устанавливается между КПХД и сетью (церемония ключей / защищённый канал),
а оператор лишь регистрирует его под присвоенным номером EKI:

```bash
bash .deploy/scripts/tk-mgmt.sh import <EKI> /путь/к/файлу-ключа
```

`файл-ключа` — текстовый файл, в котором ключ записан 32 hex-символами (16 байт, AES-128).
Скрипт проверяет формат, записывает ключ в KMS и **никогда не выводит его значение**.
Существующий номер EKI не перезаписывается (скрипт откажет; замена ключа — сначала `revoke`).
После успешного импорта файл с ключом удалите безопасно: `shred -u /путь/к/файлу-ключа`.

## 4. Шаг 2 — подготовить файл профилей

**Вариант А (простейший): симулятор «КПХД» сам сгенерирует профиль.**

```bash
bash .deploy/scripts/sim-kpdh.sh --gen 1 999990000000200 --out .deploy/profiles/load-demo.csv
```

- `1` — номер EKI (какой проверили в шаге 3);
- `999990000000200` — IMSI нового абонента (15 цифр; берите следующий свободный
  в тестовом диапазоне 99999…, текущий список — секция 3 verify-скрипта);
- создаётся файл `.deploy/profiles/load-demo.csv` со строкой
  `IMSI,EKI,E_KI,AMF` (опционально — 5-й столбец `HMAC`, см. §8).

Скрипт выведет: `profile appended to … ; plaintext Ki not stored in the file.`

**Вариант Б: файл пришёл от «КПХД» (боевой поток).**
Положите его в `~/open5gs-compose/.deploy/profiles/` и сверьте:
первая не-комментарная строка должна содержать `IMSI,EKI,E_KI,AMF[,HMAC]`;
номер EKI в строках должен совпадать с существующим ключом (шаг 3).

## Массовая прогрузка

Файл профилей — просто таблица: сколько строк, столько и абонентов
(10 или 500 — та же одна команда). Файл обрабатывается целиком: если хотя бы
одна строка испорчена — прогрузка **останавливается** (в базу ничего не
записано), скрипт показывает номер строки и причину. Повторный запуск того же
файла безопасен (идемпотентно: существующие абоненты только обновятся).

Пример — подготовить 3 UEs и прогрузить одной командой:

```bash
for i in 1 2 3; do
  bash .deploy/scripts/sim-kpdh.sh --gen 2 99999000000003$i --out .deploy/profiles/bulk.csv
done
bash .deploy/scripts/import-profiles.sh .deploy/profiles/bulk.csv
# ожидаемо: rows=3 created=3
```

Для файла от поставщика (сотни строк) достаточно проверить: в каждой строке
`IMSI,EKI,E_KI,AMF[,HMAC]`, строки, начинающиеся с `#` — комментарии, игнорируются.

## 5. Шаг 3 — прогрузить в AUC

```bash
bash .deploy/scripts/import-profiles.sh .deploy/profiles/load-demo.csv
```

Ожидаемый вывод (новый абонент):

```
import: DB_URI from stack: mongodb://mongodb:27017/open5gs?tls=true&…
[row 1] imsi=999990000000200 eki=1: subscriber created
Import complete: file=.deploy/profiles/load-demo.csv rows=1 created=1 updated=0 unchanged=0
```

Варианты для строки:
- `subscriber created` — абонент создан;
- `security keys updated` — абонент уже существовал, ключи обновлены;
- `security keys nochange` — повторная прогрузка того же файла (норма).

## 6. Шаг 4 — проверить результат

```bash
bash .deploy/scripts/verify-encrypted-stack.sh
```

Секция 3: `subscribers:` увеличилось на число прогруженных.
Опционально точный запрос по IMSI:

```bash
docker compose exec -T mongodb mongo --tls --tlsCAFile /etc/mongodb-tls-ca/ca.crt \
  127.0.0.1:27017/open5gs --quiet --eval 'print(db.subscribers.countDocuments({imsi:"999990000000200"}))'
```

`1` — профиль на месте. (Если TLS-оверлей до БД выключен — уберите `--tls`
`--tlsCAFile …` из команды; режим авто-определяется `verify-encrypted-stack.sh`,
секция 0.)

## 7. Если что-то пошло не так

Скрипт остановится с ошибкой вида `[row N] FAIL: … - import ABORTED (fail-closed)`.
**В базу ничего не записано.** Разбор по тексту ошибки:

| Текст ошибки | Причина | Что сделать |
|---|---|---|
| `TK for EKI=N not available (unknown/revoked EKI or KMS down)` | номера ключа нет в KMS, либо KMS не работает | `bash .deploy/scripts/tk-mgmt.sh meta N`; если `not present` — опечатка в EKI или ключ отозван; если KMS падает — `docker compose ps openbao` (должно быть healthy), при необходимости `docker compose restart openbao` |
| `HMAC mismatch (file corrupted, tampered, or wrong EKI/TK)` | (только для файлов с 5-м столбцом) файл исказился при передаче либо EKI не соответствует TK | перескопируйте файл из исходника; сверьте номер EKI |
| `E_KI is not 32 hex` / `bad IMSI` | нарушен формат файла | сверьте шапку файла с `.deploy/profiles/README.md` |
| `dbctl add_ue_with_slice rc=…` | проблема с записью в БД | `docker compose ps mongodb` (healthy?), повторите шаг 3 |

После устранения причины достаточно повторно выполнить **шаг 3** (он идемпотентен).

## 8. Ротация транспортного ключа (по необходимости)

Ротация — это «новый номер EKI + новые файлы + отзыв старого»:

```bash
bash .deploy/scripts/tk-mgmt.sh create 2                                   # 1) новый ключ EKI=2
bash .deploy/scripts/sim-kpdh.sh --gen 2 <IMSI> --out .deploy/profiles/load-eki2.csv   # 2) файлы с EKI=2
bash .deploy/scripts/import-profiles.sh .deploy/profiles/load-eki2.csv     # 3) прогрузить
bash .deploy/scripts/tk-mgmt.sh revoke 1                                  # 4) отозвать старый (бэкап сохранится)
```

После отзыва файлы с `EKI=1` загружаться **перестанут** (fail-closed).
Бэкап отозванного TK — в `.deploy/secrets/revoked/` (вне git, только на стенде) —
это средство последней необходимости; на него полагаться не стоит.

## Что такое HMAC, простыми словами

> **Статус: функционал под вопросом.** По умолчанию HMAC **не генерируется**
> (`sim-kpdh.sh` без флага) и **не требуется** (файл из 4 столбцов загружается
> как есть). Файлы с 5-м столбцом HMAC по-прежнему поддерживаются — импортёр
> проверяет печать при их наличии. Если решим оставить — включается флагом
> `--hmac` и режимом `IMPORT_REQUIRE_HMAC=1`.

Шифрование (AES) делает ключ в файле **невозможным прочитать** — но не защищает
от **изменений**: если один символ в `E_KI` поменяется (человек, «сломанный»
перенос), то «расшифрование» всё равно «успешно» завершится, но даст мусор —
именно его и запишет сеть в базу.

HMAC — это **«печать»** на каждой строке файла: короткий код, посчитанный по
данным строки (IMSI, EKI, E_KI, AMF) с использованием секретного «ключа печати».
Свойства печати:

- у кого есть ключ — тот **проверяет** печать (пересчитывает код и сравнивает);
- у кого ключа нет — тот **не может подделать** печать под изменённую строку;
- изменили хоть один символ в строке — печать сломана.

«Ключ печати» выводится из транспортного ключа (`HK = SHA256(TK + фиксированная
метка)`), поэтому отдельный ключ передавать не нужно.

**Практически вычисляется он руками не будет:**
- сами делаете тестовый профиль — `sim-kpdh.sh --hmac` добавляет HMAC в файл;
- файл пришёл от поставщика (КПХД) с 5-м столбцом — `import-profiles.sh`
  проверяет каждую строку перед записью. Печать не сошлась — строка не
  загружается, скрипт объясняет почему (таблица в §7);

Аналогия: пломба на посылке. Она не заменяет замок (шифрование) — она показывает,
что посылку по пути не вскрывали.

## 8.1. Повседневное управление профилями (без EKI/TK)

Изменить APN/QoS/AMBR, MSISDN, доступ (barring/отзыв), удалить абонента —
менеджер профилей `profile-mgmt.py` (ключи при этом не трогаются):

```bash
python3 .deploy/scripts/profile-mgmt.py list                  # кто есть кто
python3 .deploy/scripts/profile-mgmt.py show <imsi>           # профиль (ключи скрыты)
python3 .deploy/scripts/profile-mgmt.py update <imsi> --ue-ambr 500M --qos 9   # изменить
python3 .deploy/scripts/profile-mgmt.py revoke <imsi>         # временно заблокировать
python3 .deploy/scripts/profile-mgmt.py del <imsi>            # удалить (бэкап создаётся)
python3 .deploy/scripts/profile-mgmt.py edit <файл.csv|json>  # массовое изменение
```

Перед любым изменением скрипт сохраняет предыдущее состояние в
`.deploy/backups/` (каталог вне git) — откат: `profile-mgmt.py restore <файл-бэкапа>`.

## 9. Чего делать НЕ нужно

- Не записывайте plaintext-ключи в файлы загрузки — для этого и есть EKI/TK.
- Не удаляйте секреты из OpenBao вручную (`bao kv delete` и т.п.) — только `tk-mgmt.sh revoke`.
- Не меняйте конфиги Diameter (`hss.conf/mme.conf/pcrf.conf/smf.conf`) и сертификаты
  в `.deploy/docker/diameter/` — они читаются при старте служб; при необходимости
  регенерации — `bash .deploy/scripts/generate-diameter-tls.sh`.
- Не запускайте `docker compose down -v` и не удаляйте `.deploy/docker/local-data/`
  (там база данных и KMS — их потеря необратима).
- Не трогайте другие контейнеры стенда (Portainer, GenieACS, NMS).
