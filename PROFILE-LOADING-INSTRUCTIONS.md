# Процедура: прогрузка профилей абонентов в AUC (через файл, с использованием транспортного ключа EKI/TK)

**Область применения.** Настоящая инструкция определяет порядок загрузки
профилей абонентов (SIM/UICC) в AUC ядра open5gs (коллекция `subscribers`)
из загрузочного файла с использованием транспортного ключа (TK),
идентифицируемого по EKI. Область действия — ядра 4G (HSS) и 5G (UDM/UDR).

**Сопутствующие документы:** `EKI-TK-ENCRYPTION.md` (архитектура, иерархия
ключей, ограничения), `.deploy/profiles/README.md` (спецификация формата
загрузочного файла).

## 1. Свойства защищённости потока

- Ключ абонента (Ki) **не содержится** в загрузочном файле в открытом виде.
  Файл содержит `E_KI = AES-128-ECB(TK, Ki)` и идентификатор транспортного
  ключа `EKI`.
- Значение TK хранится исключительно в KMS (OpenBao, KV v2) по пути
  `secret/transport-keys/eki-<EKI>`; в файлах, системах контроля версий и
  журналах не присутствует.
- Загрузка выполняется по принципу **fail-closed**: любая ошибка
  (неизвестный или отозванный EKI, недоступность KMS, нарушение формата,
  расхождение HMAC при наличии соответствующего столбца) прерывает загрузку
  целиком — изменения в базе данных **не выполняются**.
- Повторная загрузка того же файла идемпотентна: существующие записи
  обновляются, дубликаты не создаются.

## 2. Исходные данные

| № | Исходные данные | Примечание |
|---|---|---|
| 1 | Доступ к хосту ядра с работающим стеком (docker compose) | оператор ядра |
| 2 | Загрузочный файл от центра персонализации (КПХД) / поставщика | формат — §5 |
| 3 | Номер EKI, согласованный с выдающей стороной ключа | зарегистрирован в KMS — §4 |

## 3. Предварительная проверка

```bash
bash .deploy/scripts/tk-mgmt.sh meta <EKI>
```

- Ожидаемый результат: `current_version: N` — транспортный ключ с номером
  `<EKI>` зарегистрирован в KMS;
- `not present in the KMS` — ключ не зарегистрирован или отозван: выполнить
  §4 (регистрация) либо уточнить номер EKI у выдающей стороны.

## 4. Регистрация транспортного ключа

### 4.1. Ключ, сформированный в сети

```bash
bash .deploy/scripts/tk-mgmt.sh create <EKI>
```

Ключ (AES-128, 32 hex-символа) генерируется и сохраняется в KMS; значение
нигде не выводится. Существующий EKI не перезаписывается.

### 4.2. Ключ, полученный от поставщика (КПХД)

Ключ устанавливается между КПХД и сетью защищённым каналом (церемония
обмена ключами); оператор регистрирует его в KMS под согласованным номером EKI:

```bash
bash .deploy/scripts/tk-mgmt.sh import <EKI> <файл-ключа>
```

`<файл-ключа>` — текстовый файл, содержащий ключ в виде 32 hex-символов
(16 байт). Скрипт проверяет формат, сохраняет ключ в KMS и не выводит его
значение; существующий EKI не перезаписывается.

После успешной регистрации файл ключа подлежит безопасному удалению:

```bash
shred -u <файл-ключа>
```

## 5. Контроль загрузочного файла

Формат (спецификация — `.deploy/profiles/README.md`):

```
# строки, начинающиеся с '#', — комментарии
IMSI,EKI,E_KI,AMF[,HMAC]
<14–15 цифр>,<целое > 0>,<32 hex>,8000[,<64 hex>]
```

| Столбец | Описание |
|---|---|
| `IMSI` | 14–15 десятичных цифр |
| `EKI` | Идентификатор транспортного ключа; должен соответствовать ключу, зарегистрированному в KMS |
| `E_KI` | `AES-128-ECB(TK_EKI, Ki)`, 32 hex-символа |
| `AMF` | 5G-поле AMF; значение по умолчанию — `8000` |
| `HMAC` (опционально) | Контроль целостности строки; проверяется загрузчиком при наличии столбца |

Сетевой `OPc` выводится сетью при загрузке как `OPc = AES128(OP, Ki)`
(3GPP TS 35.208 Annex C, MILENAGE) и в файл **не включается**.

Массовая загрузка: файл представляет собой таблицу — по одной строке на
абонента. Файл обрабатывается целиком: нарушение в любой строке прерывает
загрузку, изменения в базе данных не выполняются.

## 6. Загрузка в AUC

```bash
bash .deploy/scripts/import-profiles.sh <загрузочный-файл>
```

Типовой вывод для новых абонентов:

```
[row 1] imsi=<IMSI> eki=<EKI>: subscriber created
Import complete: file=<загрузочный-файл> rows=N created=N updated=0 unchanged=0
```

Статусы строк: `created` — профиль создан; `updated` — ключи обновлены у
существующего абонента; `nochange` — изменений не требуется (повторная
загрузка).

## 7. Подтверждение результата

Проверить наличие профилей в AUC по IMSI (через средства управления ядром —
WebUI, либо непосредственно в БД): запись `subscribers.<imsi>` должна
содержать полный профиль (блок `security`, сессии). Число абонентов
увеличилось на количество успешно загруженных строк.

## 8. Обработка ошибок

Скрипт прерывается сообщением вида
`[row N] FAIL: <текст> - import ABORTED (fail-closed)`; изменения в базе
данных не выполняются. После устранения причины повторить §6.

| Текст ошибки | Причина | Действия |
|---|---|---|
| `TK for EKI=N not available (unknown/revoked EKI or KMS down)` | Ключ не зарегистрирован/отозван либо KMS недоступна | `tk-mgmt.sh meta N`; проверить состояние KMS |
| `HMAC mismatch (file corrupted, tampered, or wrong EKI/TK)` | (только файлы с 5-м столбцом) файл повреждён при передаче либо EKI не соответствует TK | Повторить передачу файла из исходника; сверить номер EKI |
| `E_KI is not 32 hex` / `bad IMSI` | Нарушение формата файла | Сверить файл со спецификацией (§5) |
| `dbctl add_ue_with_slice rc=…` | Сбой записи в БД | Проверить состояние СУБД; повторить §6 |

## 9. Ротация транспортного ключа

1. `bash .deploy/scripts/tk-mgmt.sh create <EKI+1>` — либо `import` нового
   ключа, полученного от поставщика (§4.2);
2. КПХД формирует загрузочные файлы с `EKI=<EKI+1>`;
3. `bash .deploy/scripts/import-profiles.sh <новый-файл>`;
4. `bash .deploy/scripts/tk-mgmt.sh revoke <EKI>` — отзыв прежнего ключа
   (служебная копия хранится вне системы контроля версий и используется
   исключительно как средство последней необходимости).

После отзыва загрузка файлов с прежним EKI не выполняется (fail-closed).

## 10. Требования

1. В загрузочные файлы не допускается включение ключей абонентов в открытом
   виде — для этого предусмотрен механизм EKI/TK.
2. Удаление ключей из KMS выполняется только `tk-mgmt.sh revoke`; прямые
   операции с хранилищем (вручную) запрещены.
3. Файл ключа, полученный от поставщика, хранится в защищённой среде,
   пересылается только защищённым каналом и безопасно удаляется после
   регистрации (§4.2).
4. Загрузочные файлы, содержащие eKi, не содержат открытых ключей и могут
   пересылаться стандартными средствами передачи файлов (scp/SFTP).
